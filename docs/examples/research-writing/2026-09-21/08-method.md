# 高解像度入力：縮小で見えにくくなる細部を残す

> 見本08：手法を説明する。架空のプロジェクト。

- **目的**：細い傷の見逃しを減らす。
- **変更点**：入力画像を224×224 → 448×448にする。
- **仕組み**：細部を表す画素を多く残した状態で、モデルを学習する。
- **現在の根拠**：開発F1は平均+1.8ポイント。推論時間は2.4倍。

## 具体例：幅4画素の傷はどうなるか

| 段階 | 画像サイズ | 傷の幅の目安 |
|---|---|---|
| 元画像 | 896×896 | 4画素 |
| 従来の入力 | 224×224 | 1画素 |
| 現在の入力 | 448×448 | 2画素 |

- **期待する変化**：傷を表す画素が増え、背景と見分けやすくなる可能性がある。
- **表の意味**：単純な縮尺の目安。実際の見え方は補間・向き・コントラストにも依存する。

## 処理：どこを変えるか

1. 元画像を読み込む。
2. モデルへ渡す前に、448×448へリサイズする。
3. 448入力でモデルを学習し直す。
4. 同じ448入力で評価する。

- **比較で固定するもの**：モデル構造、学習データ、学習率など。
- **コスト**：画素数は4倍。実行時間やメモリの倍率は、機器・実装ごとに測る。

## 前提：どんな問題に使うか

- **必要な条件**：分類に使える細部が、元画像に写っている。
- **別の対応が必要な例**：反射で傷が見えない画像、分類基準が曖昧な画像。
- **検証すべきこと**：細部を残した入力を、モデルが分類に利用できるか。

## 実測：この例では何が分かったか

- **全体**：macro F1は3 seed平均81.6 → 83.4。[実験001](02-finding.md)
- **細かい傷**：seed 0の100枚では正解60 → 78枚。
- **推論時間**：10 → 24ms/枚。同一機器・batch size 16。
- **未確認**：学習時間、448より大きい入力の利得、別の撮影条件への効果。
